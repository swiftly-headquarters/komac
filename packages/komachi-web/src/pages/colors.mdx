## Usage

Reach for semantic tokens rather than raw Tailwind colors. They let your UI follow light and dark mode automatically and keep components consistent from theme to theme.

#### Correct

```tsx
<div className="bg-komachi-base text-komachi-default border-komachi-hairline">
  <button className="bg-komachi-brand text-white">Primary</button>
  <button className="bg-komachi-control text-komachi-default">Secondary</button>
</div>
```

#### Incorrect

```tsx
{
  /* Never use raw Tailwind colors */
}
<div className="bg-white dark:bg-gray-900 text-black dark:text-white">
  <button className="bg-blue-500">Primary</button>
</div>;
```

> This is enforced by lint: the `no-primitive-colors` rule reports any raw Tailwind color such as `bg-blue-500`.

## Mode

Put `data-mode` on a parent element to choose light or dark mode. Do not use Tailwind's `dark:` variant; semantic tokens already handle dark mode through CSS `light-dark()`.

```tsx
// Set mode on html or body
<html data-mode="light">  // Light mode
<html data-mode="dark">   // Dark mode

// Components automatically adapt - no dark: variants needed
<div className="bg-komachi-base text-komachi-default" />
```

## Themes

A theme replaces the values behind semantic tokens while the token names stay the same. Komachi includes one theme, `komachi`, which is active by default without any `data-theme` attribute. You can add your own with the theme generator.

### Theme Generator

Every theme is declared in one shared config and compiled into CSS files, which keeps all themes consistent.

```bash

# List all tokens and their theme overrides

pnpm --filter komachi codegen:themes --list

# Generate theme CSS files

pnpm --filter komachi codegen:themes

# Preview changes without writing files

pnpm --filter komachi codegen:themes --dry-run
```

Theme config: `packages/komachi/scripts/theme-generator/config.ts`

### Creating a New Theme

Declare your overrides in the config file. List only the tokens that differ; the rest inherit from the base komachi theme.

```ts
// In scripts/theme-generator/config.ts
export const THEME_CONFIG: ThemeConfig = {
  color: {
    "komachi-base": {
      newName: "",
      theme: {
        komachi: {
          light: "var(--color-white, #fff)",
          dark: "var(--color-black, #000)",
        },
        // Add your theme override
        myTheme: {
          light: "#f0f4f8",
          dark: "#1a1f2e",
        },
      },
    },
    // ... other tokens
  },
};

// Add to available themes
export const AVAILABLE_THEMES = ["komachi", "myTheme"] as const;
```

Finish by running `pnpm codegen:themes` to produce the CSS.

## Semantic Tokens

Semantic tokens organize colors by what they are for. Pick the token that fits the element's role, not the shade you have in mind.

Tokens are named for their **role**, never their hue. `bg-komachi-danger` describes intent and does not promise a particular red; its value can vary by theme or color mode without any change to your component code.

### Semantic Status Colors

Every status color has two forms: a solid one for icons and indicators, and a `-tint` one for background fills behind content (such as `Badge` or `Banner`).

Use the solid `bg-komachi-*` token for status dots, `fill-komachi-*` for icons, and `border-komachi-*` or `ring-komachi-*` for borders and rings. Banners and badges rely on the `-tint` form at different opacities.
